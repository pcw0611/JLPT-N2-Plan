# N2 文法 SPEED RUN 수록 문법 점검

검토일: 2026-11-01. 요청 범위는 점검이며 문제 소스 수정·배포·기존 성적 정정은 하지 않았다.

## 대상과 확인 범위

- 실행 소스: `jlpt-calendar-site/public/exams/n2-grammar-speedrun.html`.
- 생성 데이터: `scripts/n2_grammar_dataset.json`. 두 파일의 수록 데이터는 완전히 동일하다.
- 001~200의 문형명·접속·빈칸·완성 예문·의미·접속 칩을 읽고 검토했다. 개별 문법의 모든 용법을 사전·교재 원문과 전수 대조한 검증은 아니다.
- 자체 제작 학습 문제다. 공식 문제 전사나 공식 N2 문법 목록과의 일치 검사는 아니다. 실제 브라우저의 현 배포 화면은 이 작업에서 조작하지 않았다. 이전 작업에서 브라우저 연결이 끊긴 상태이므로 같은 실패를 재시도하지 않았다.
- 실제 JavaScript의 `isSynonym`과 `generateQuestions`를 Node VM에서 실행했다. DOM·네트워크·학습 DB 쓰기를 포함하지 않는 검사다.

## 결론

문형을 떠올리는 반복 연습 자료로는 사용할 수 있지만, **정답 유일성과 접속 설명이 보장된 N2 전 범위 진단 시험으로 취급하면 안 된다.** 특히 접속을 배우는 학습자에게는 잘못된 ‘전용’ 표시가 오개념을 만들 수 있다.

## P1 — 복수 정답이 실제 선택지로 생성된다

선택지는 문항별 검토 목록이 아니라 전체 200개 문형에서 무작위로 추출한다(HTML `generateQuestions`, 약 5605행). 동의어 필터만으로 문맥상 대체 가능한 표현을 모두 배제하지 못한다. 아래 네 조합을 실제 생성 함수 출력에서 확인했다.

| 문항 | 빈칸 문장 | 지정 정답 | 함께 생성된 자연스러운 대안 |
| --- | --- | --- | --- |
| 099 | 標高が高くなる（　）、気温が下がってきた。 | にしたがって | につれて |
| 100 | 激しい風雨（　）、多くのファンが集まった。 | にもかかわらず | をものともせずに |
| 145 | 東京オリンピックの開催（　）、都市のインフラ整備が急速に進んだ。 | を契機として・を契機に・をきっかけに | を機に |
| 170 | こんなに山盛りの料理を、一人で全部食べられる（　）。 | わけがない | はずがない |

100번은 표현의 관점·뉘앙스가 완전히 같지는 않지만, 어느 쪽도 이 문장만으로 문법적 오답으로 배제할 수 없다. 145번 등은 선택지 자체가 완성형이 아닌 여러 문형을 묶은 표제라는 별도 문제도 있다.

이 네 쌍은 `isSynonym`이 모두 false를 반환한다. 채점은 지정 표제와 같거나 이 함수가 true일 때만 정답이다(약 6081행). 따라서 **문법적으로 성립하는 대안이 선택되어도 오답 처리될 수 있다.** 해석 ON이 일부 의미 판별에 도움을 주더라도 099·145처럼 한국어 의미까지 겹치는 조합을 해결하지 못한다.

추가 잠정 후보: 114의 `国籍や年齢によらず`와 148의 `国籍や年齢を問わず`. 둘은 해당 문맥에서 대체 가능하고 필터도 false지만, 이번 반복 생성 로그에서는 이 두 선택지의 동시 출현을 확보하지 못했다. 위 네 재현 사례와 구분한다.

권장: 문항마다 검토한 실제 완성형 선택지를 고정한다. 모든 선택지를 문장에 대입해 정답이 하나인지 확인한다. 복수 정답 허용 훈련이라면 허용 정답을 해당 문항에 명시한다.

## P1 — 접속 설명·‘전용’ 표시에 오류가 있다

| 번호 | 현재 표시·설명 | 문제와 교정 방향 |
| --- | --- | --- |
| 014 がち | ‘동사 ます형 전용’ | 같은 항목의 connection은 N＋がち도 허용한다. `欠席がち`처럼 명사도 가능하다. ‘동사 ます를 뺀 형태 / 일부 명사’로 표시한다. |
| 024 気味 | ‘동사 ます형 전용’ | 같은 항목에 N＋気味가 명시되어 있다. `風邪気味`도 가능하므로 전용 표시는 잘못이다. |
| 065 てたまらない | `conn_strict=true`, ‘동사 て형 전용’ | 데이터 자체가 `い형＋くて`, `な형＋で`도 함께 적고 있다. `寒くてたまらない`가 가능하다. |
| 080 ところを | 접속 칩 ‘명사 직결’, connection에서 い형용사 누락 | 실제 예문은 `お忙しいところを…`로, い형용사 `忙しい`에 연결된다. 화면 안에서 실제 예문과 일반 접속 설명이 맞지 않는다. |
| 085 ないことには | ‘동사 ない형 전용’ | 같은 항목의 connection은 형용사·명사의 부정도 명시한다. ‘동사만’이라는 전용 표시는 철회해야 한다. |
| 086 ないことはない | ‘동사 ない형 전용’ | 같은 항목의 connection은 `い형용사くない`, `な형용사でない`도 허용한다. |
| 060 つつ(も)・ながら(も)・つつある | 표제 전체에 ‘동사 ます형 전용’ | つつ 계열의 규칙을 ながら(も) 전체에 적용할 수 없다. `残念ながら`처럼 명사·な형용사 계열도 있다. 각 문형·용법을 분리한다. |
| 140 ようでは | 사전형으로 한정한 접속·칩 | 실제 예문은 `間違えているようでは`다. 적어도 동사 보통형의 ている 등도 반영해야 한다. |
| 143 わけにはいかない | 접속·칩은 사전형 중심 | 실제 예문은 `遊んでいるわけにはいかない`다. 진행·지속 상태에 대한 사용과 ない형 결합을 함께 설명해야 한다. |
| 195 ごとき | Nの＋ごとき만 제시 | 실제 예문 `私ごとき`는 명사 직접 연결이다. 경시·자기 낮춤과 비유 용법의 접속을 구분한다. |

‘현재 빈칸 바로 앞의 형태’와 ‘그 문형이 허용하는 전체 접속’은 다른 정보다. `conn_badge`와 `conn_chips`를 그 두 역할로 명확히 분리해야 한다. 문형 일반에 대한 ‘전용’이라는 단정은 예문 하나만으로 생성하지 않는다.

또한 ‘ます형’만 적으면 `読みます` 자체를 붙이는 것으로 오해할 수 있다. 이 프로젝트에서는 **‘ます를 뺀 형태: 読み’**를 명시하는 편이 안전하다. 東京外国語大学의 활용표도 `ます形=よみます`와 `連用形=よみ`를 구분한다.

## P2 — 동의어 필터의 의미 분류도 재검토해야 한다

실제 함수 실행 결과:

- 016 `かねない`와 017 `かねる`: true. ‘나쁜 결과가 생길 가능성’과 ‘사정상 하기 어려움’을 같은 의미로 취급한다.
- 035 `ことはない`와 086 `ないことはない`: true. ‘그럴 필요 없음’과 ‘아닌 것은 아님’을 같은 의미로 묶는다.
- 반대로 위 복수 정답 네 쌍은 모두 false다.

여기에는 두 역할이 혼재한다. ‘비슷해서 오답 후보에서 제외할 것’과 ‘정답으로 인정해도 되는 것’은 같은 기준이 아니다. 일반 생성기는 true인 쌍을 미리 선택지에서 빼므로, **위 true 쌍 때문에 정상 화면에서 실제 오채점이 발생했다고 확인한 것은 아니다.** 다만 중요한 대조 연습이 사라지고, 이 함수를 정답 판정에 재사용하는 기준 자체도 잘못되어 있다.

권장: 의미가 같은 문형, 문맥에 따라 대체 가능한 문형, 뜻이 반대여서 구별해야 하는 문형을 구분한다. 정답 판정은 문항별 허용 답으로 처리한다.

## P2 — ‘전 범위·1:1 완전 마스터’와 실제 수록 범위가 다르다

- 항목 200개, 고유 ID 200개, 고유 번호 200개: 정상.
- 표제에 `／`, `・`, ` / `로 여러 형태를 묶은 항목이 37개다. 모두 다른 뜻이라는 의미는 아니지만, 항목 하나를 맞혔다고 표제에 묶인 모든 문형·용법을 확인한 것은 아니다.
- 034는 `ことになる・ことにはならない・ことにする`를 묶지만 예문은 `ことになった` 하나다.
- 060은 역접 `つつも`만 출제하며, 변화 `つつある`를 따로 확인하지 않는다.
- 142는 `ようになる・ようにする`를 묶지만 예문은 `ようになってきた` 하나다.
- `おそれがある`, 독립 문형 `得る／得ない`, `に関して`, `について`, `に基づいて`, `に比べて`, `にかかわらず`, `にひきかえ`는 독립 출제 항목이 없다. 일부가 해설·동의어 목록에 등장하는 것과 실제 출제되는 것은 구별한다. 이 목록은 보강 후보이며 공식 필수 문형 목록이라고 단정하지 않는다.
- 공식 JLPT는 현 시험의 어휘·한자·문법 항목을 망라한 출제기준 목록을 발행하지 않는다. 따라서 이 자체 목록을 ‘공식 N2 전 범위 완전 수록’으로 인증할 근거는 없다.

권장: ‘N2 대비 문법 연습 200항목’으로 범위를 표시하고, 한 문형의 한 용법마다 복수의 새 문맥을 제공한다. N2 합격을 우선하므로 확장 표현의 개수보다 핵심 접속·유사 문형 대조를 우선한다.

## P2 — 해설·학습 측정의 추가 문제

- 026~035의 `diff_point`가 비어 있다(10건). 유사 표현 차이 해설이 빠진다.
- 057 해설은 `がてら/をかねて`를 함께 ‘이동 수반’으로 제한한다. `をかねて` 자체에 이동이 필수는 아니다. 예: `お祝いを兼ねて食事会を開く`.
- 183의 っぱなし는 ‘방치·불만’뿐 아니라 `立ちっぱなし`처럼 동작·상태의 지속도 다뤄야 한다. 같은 항목의 diff에 이 예가 있지만 핵심 설명에는 빠져 있다.
- 193의 접속 칩은 `仕事ぶり`를 ‘동사 ます형 어간’ 예시 아래 넣지만 `仕事`는 이 표현에서 명사다. `働きぶり` 같은 동사 어간 예와 나누어 표시한다.
- 105의 ‘99% 이상 확신’, 199·200의 ‘최고 격식’은 측정 가능한 수치나 일관된 절대 등급처럼 외우게 하지 말고 표현의 기능·관계를 설명해야 한다.
- 보기에는 문장에 그대로 들어갈 형태 대신 문형 표제가 표시된다. 예를 들어 017의 정답 표제는 `〜かねる`, 실제 정답 삽입은 `かねます`다. 009는 빈칸에 `か鳴らないかのうちに` 전체가 필요하다. 이것은 문형 재인 훈련이며 활용·접속을 직접 생성할 수 있는지 평가하는 훈련과는 다르다.
- 한국어 해석과 접속 힌트가 있는 연습이며, 문항마다 즉시 채점·해설을 보여 준다. 프로젝트의 ‘시험 화면 일본어 / 최종 제출 후 해설’ 규격과 다르므로 연습 모드로 분리해야 한다. 현재 점수를 독립적인 실전시험 점수로 해석하지 않는다.
- 자동 저장 코스명은 전체 200개임에도 `N2 전범위 150제 종합`으로 남아 있고 c4 이름도 없다(약 6251행). 모름은 별도 집계 없이 일반 오답에 들어가며 정답 문항을 포함한 전체 응답·문항별 시간은 제출하지 않는다. 기록 신뢰도 점검도 필요하다.

## 실행 검사 결과와 한계

- 필수 ID·번호 중복 없음, 200문항 모두 빈칸 정확히 1개.
- 200문항 모두 `빈칸에 sentence_ja_target 삽입 = 저장된 sentence_ja` 일치. 이 검사는 문자열 전사 일치이며 문법·자연스러움 인증이 아니다.
- 실제 생성 함수에서 위 복수 정답 후보 조합 4건 동시 출현 확인.
- 200개 문형이 모두 올바르다는 판정이나 전체 문항의 유일 정답 검증 완료를 선언하지 않는다. 무작위 보기의 가능한 조합 전체는 문법적으로 전수 검증하지 않았다.
- 공식 교재의 문형 목록·문항 원문과 대조하지 않았다. 브라우저 전체 응시·실제 저장 API는 실행하지 않았다. 테스트 결과는 실제 학습 기록에 넣지 않았다.

## 우선순위

1. 문항별 보기와 허용 정답을 검토해 복수 정답 문제 해결.
2. 접속·접속 칩·전용 표시 교정. `ます를 뺀 형태` 등 조작 가능한 설명 사용.
3. 합쳐진 문형·용법을 분리하고 핵심 접속의 수록 공백 보완.
4. 모름·미응답·선택 답·문항별 시간을 보존하고 실전시험과 반복 연습 기록을 분리.

## 수정 후 현재 상태 — 원래 기능 유지

사용자는 문법 오류 수정을 요청했으며 모드·선택지·저장 방식 변경을 원하지 않았다. 작업 중 추가했던 점검/학습 모드 분리, 실제 형태 선택지, 수동 저장, 214항목 확장은 사용자 지적 후 모두 철회했다. 해당 변경을 현재 제품 사양으로 간주하지 않는다.
